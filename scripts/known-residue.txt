# ─────────────────────────────────────────────────────────────────────────────
# CLASS 2 — cortex's postinstall, outside D6's reach BY CONSTRUCTION.
#
# THIS IS THE REAL GAP, and it is the one that matters to the epic.
#
# cortex's scripts/postinstall.sh creates runtime directories and conditionally
# copies a relay policy template. None of it is declared in cortex's `owns:`
# block, and `arc purge` only deletes what a package DECLARES it owns — so
# `untangle: CLEAN` is printed truthfully while all of this is still on disk.
# arc names this failure mode itself: docs/design-factory-type.md, arc#401
# residual risk (c), "a package that writes outside everything it declares is
# outside D6's reach by construction".
#
# The fix is cortex-side and small: declare these under `owns.state` /
# `owns.config` in cortex's arc-manifest.yaml, at which point purge deletes them
# and D6 verifies it. relay-policy.yaml is the one judgement call — it is a
# template copied only when absent, so it is arguably `owns.userData` (kept, but
# then NAMED in the refusal line, which is the honest outcome either way).
#
# OWNER: cortex — cortex#2520 (OPEN) carries the owns-declaration ask. This is
# the line item that keeps the epic's DoD from passing.
# ─────────────────────────────────────────────────────────────────────────────
./.claude/events
./.claude/events/published
./.claude/events/raw
./.claude/hooks
./.claude/logs
./.claude/relay
./.claude/relay/relay-policy.yaml

# ─────────────────────────────────────────────────────────────────────────────
# CLASS 2b — EMPTY PARENT DIRECTORIES. Previously filed under Class 2 as
# cortex's to declare. That was over-claiming, and the correction matters
# because it changes who can fix them.
#
# These four are not things cortex created and forgot to declare. They are the
# PARENTS of paths cortex does declare and arc does delete:
#
#   ./.local/state, ./.local/state/metafactory
#       arc deletes ~/.local/state/metafactory/cortex — the purge report says so
#       in as many words ("deleted: …/.local/state/metafactory/cortex"). The two
#       now-empty parents remain.
#   ./Library, ./Library/LaunchAgents
#       arc removes the rendered plists; the directory stays.
#
# So even a perfect `owns:` declaration in cortex would not remove them: the
# leaf was declared, was deleted, and the empty parent is what is left.
#
# TWO DIFFERENT OWNERS, and neither is cortex:
#
#   ./.local/state + ./.local/state/metafactory — arc does not prune parent
#     directories it emptied. That is a small, defensible arc behaviour (pruning
#     upward is how a package manager deletes a directory another package is
#     about to use, or one the operator created), but it is worth naming as a
#     behaviour rather than leaving it looking like a cortex bug. Recorded as an
#     observation, not filed: the cost is two empty directories.
#
#   ./Library + ./Library/LaunchAgents — macOS-standard, SHARED directories that
#     no package may delete. Every launchd-using application on the machine uses
#     ~/Library/LaunchAgents. Removing it because one package's plist went would
#     be straightforwardly destructive. These are permanently correct residue
#     and will still be here when the rest of this file is gone.
#
# OWNER: arc (the two state parents, as a behaviour note) / nobody (the Library
# pair — deleting them would be a bug, not a fix).
# ─────────────────────────────────────────────────────────────────────────────
./.local/state
./.local/state/metafactory
./Library
./Library/LaunchAgents

# ─────────────────────────────────────────────────────────────────────────────
# CLASS 3 — settings.json, deliberately never deleted.
#
# arc registers a package's Claude Code hooks INTO ~/.claude/settings.json and
# removes only that package's entries at purge, keyed on the `_arc_pkg` tag
# (arc: src/lib/hooks.ts). The file itself is the operator's, shared with every
# other tool that writes to it, so arc will not delete it — correctly.
#
# The harness therefore checks the file's CONTENT the only way that matters:
# arc's own D6 verdict re-reads settings.json by that tag and reports a
# surviving hook registration as residue (A4.2 asserts CLEAN). A leftover hook
# would fail there even though the file is baselined here.
#
# OWNER: nobody — this is correct behaviour, and it will still be here when the
# rest of this file is gone.
# ─────────────────────────────────────────────────────────────────────────────

# ─────────────────────────────────────────────────────────────────────────────
# CLASS 4 — the gh CLI's own state. ENVIRONMENT-CONDITIONAL; read this before
# deleting it as stale.
#
# `gh` is declared in this manifest's `tools:` block, and compass-core and
# code-review both shell out to it. gh writes a telemetry device-id under
# XDG_STATE_HOME the first time a member actually invokes it, so the file is
# created by the composition USING a host tool, not by the composition
# installing anything. Nothing purges it because nothing owns it.
#
# WHY IT MAY SHOW AS STALE, AND WHY THAT IS NOT A REASON TO DELETE IT: on a
# developer machine where gh has run before, the redirected XDG_STATE_HOME is
# still fresh but the harness's baseline is taken after a warm-up, and the
# device-id happens to land before it — so these paths never appear in the diff
# and the harness reports the entry as stale. On a fresh CI runner they do
# appear, and without this entry A5.9 goes red on them. The entry is therefore
# correct on one machine and stale on another, which is unusual enough to say
# out loud rather than let someone "tidy" it away and rediscover it in CI.
#
# OWNER: nobody — it is the measuring environment's trace, the same category as
# the bun caches the harness excludes wholesale under ./.cache. It sits here
# rather than in that exclusion only because it lives under .local/state, where
# cortex's real state also lives and must stay visible.
# ─────────────────────────────────────────────────────────────────────────────
./.local/state/gh
./.local/state/gh/device-id
